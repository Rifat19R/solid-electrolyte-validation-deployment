<b>Nested inner/outer split procedure</b> (main-text Methods; the nested internal validation): for every outer fold in every internal-validation regime (A/B/C), hyperparameters are tuned using an 80/20 inner split of THAT fold's own outer-train partition only (inner_early_stop_split, stop_fraction=0.2, same seed convention as outer-fold construction) — the outer-test rows are never seen by inner tuning, and for LOMFO the held-out major family is excluded from outer-train entirely, so it cannot appear in inner tuning either. <b>Pooled MAE vs. macro-family MAE</b> (used throughout Results/SI tables): pooled (micro-average) MAE weights every scored ROW equally, regardless of which chemical family it belongs to (sample_weighted_mae, algebraically identical to computing MAE directly over all rows). Macro-family MAE weights every FAMILY equally regardless of its row count (macro_family_mae, the unweighted mean of each family's own MAE) — a family with 1 row and a family with 130 rows contribute equally to this statistic, making it far more sensitive to a single small family's outlier behavior than pooled MAE is.

Why the external transfer was not rerun after the nested-CV correction, and what that means for comparing internal and external numbers. The internal-validation regimes (A/B/C, nested per N4b; main-text Methods) and the external transfer (N6) answer two related but procedurally different questions. Nested internal CV re-tunes hyperparameters independently inside every outer fold and reports the resulting out-of-fold error — it estimates the expected performance of the whole tuning-and-fitting PROCEDURE, repeated many times on different train/test partitions of the same 449-row population. N6, by contrast, evaluates eight FINAL, already-frozen configurations (one hyperparameter set per model, selected once via N3's original train/validation split, before any internal-CV regime or external label was touched) refit once on the full 449-row development population and scored once against the external cohort. These are not the same estimand: nested-CV's internal MAE is a procedure-level estimate with its own fold-to-fold variance (quantified directly in Supplementary Note 16's repeated-seed sensitivity), while N6's external MAE is a single evaluation of one frozen configuration. Rerunning N6 under each new internal-CV variant this study explored would not fix this asymmetry — it would multiply the number of one-shot external evaluations, which the pre-specified hash-locked protocol was explicitly designed to prevent (run_count=1, authorized=True, enforced by artifacts/frozen/external_transfer_lock.json and a guard in scripts/transport_analysis/n6_external_transfer.py that refuses to produce a second primary result). Every internal-vs-external comparison in this study therefore compares a procedure-level internal estimate against a single frozen-configuration external evaluation by construction, not by oversight; we report this asymmetry explicitly rather than treat the two numbers as directly equivalent estimators of the same quantity.

<b>Part H.1. ### Part I. Additional post hoc robustness controls


Seven additional post hoc robustness controls were run for this submission, each specified in a written, hashed plan (`reports/remediation/specs/`) before any number was computed, none rerunning the frozen external transfer or opening the frozen 113-row OBELiX test split. The specifications and their SHA-256 hashes (`reports/remediation/specs/`, `HASHES.txt`), the scripts (`scripts/analysis/issue*.py`) and the result records (`artifacts/authoritative/issue*.json`) are included in the release.


#### Supplementary Note 30. Common-support LOMFO sensitivity


LOMFO (regime C) scores only the 396 development-population rows belonging to a major family (n>=15); regimes A and B score all 449. Restricting regimes A and B's internal pooled MAE to this identical 396-row common support (row-count-weighted recombination of already-frozen per-family MAE; no retraining) gives, for the corrected 8-model view: A's median |MAE gap| 0.6106 (vs. 0.4531 full-support), B's 0.6397 (vs. 0.6810 full-support) -- the point estimate still favors A over B on this restricted population, as it does under full support, but by a much narrower margin (0.61 vs. 0.64, against 0.45 vs. 0.68 under full support); the 95% bootstrap CI on the B-minus-A delta includes zero ([-0.2952, 0.3655]). Rank agreement moves the other way: under full support, the corrected B-minus-A Spearman and Kendall differences no longer exclude zero (Supplementary Note 27), but restricting to the common support restores a result that excludes zero in A's favour (Spearman rho delta -0.2857, 95% CI [-0.5476, -0.0952]; Kendall tau delta -0.3571, 95% CI [-0.6429, -0.0714]); regret is unchanged (delta +0.1471, 95% CI [0.0337, 0.2638], excluding zero both times). <b>Conclusion: on the corrected 8-model view, the common-support restriction no longer flips the median-|MAE-gap| point estimate to favor B -- it still favors A, just more narrowly -- while it restores statistical significance for the rank-agreement comparisons that the primary full-cohort analysis lost after the pooled elemental-property model's representation was corrected (Supplementary Note 27); regret is robust to the restriction either way.</b>


#### Supplementary Note 31. Training-size-matched control for Family-GroupKFold


Regime B's fold 0 removes NASICON plus five smaller families (213/449 = 47.4% of the pool) from training, confounding training-size loss with family-exclusion distribution shift. A plain random row-level holdout of the identical per-fold test size (ignoring family membership; 3 deterministic seeds, full nested per-fold retuning identical to the primary protocol) stays within the same order of magnitude as regime A for every model, including the two that catastrophically blow up under regime B itself: ridge (A = 1.410; B = 143.129; size-matched control = 1.410, 1.299, 1.281 across the 3 seeds) and the shallow MLP (A = 1.029; B = 969.424; size-matched control = 1.154, 1.153, 1.137). <b>This directly confirms the manuscript's mechanism claim</b>: the extrapolation failure is caused by removing an entire chemical family's feature distribution from training, not by training-set size reduction alone. Every other model shows only modest degradation under the matched-size control, comparable to its ordinary degradation under regime B.


#### Supplementary Note 32. Strictly fold-local robust shift-distance correction


Supplementary Note 20's robust shift-distance fix used, as its near-degeneracy-guard denominator, each feature's standard deviation over the full 449-row development population -- a population that includes each fold's own held-out rows' feature values (never labels; the diagnostic remains fully target-free throughout). A corrected version instead uses, per fold, the median of every <i>other</i> fold's own train-only standard deviation as the reference (a perfectly fold-blind reference is not constructible for a K-fold partition of a fixed pool -- every row is, by construction, a training-set member of every fold except the one where it is held out, so any non-trivial population-style reference necessarily touches it somewhere; this construction removes the specific problem that a fold's own unusually large exclusion, such as regime B's fold 0, no longer single-handedly determines the threshold it is judged against). Checked directly, not assumed: the corrected reference produces <b>identical per-fold dimension-drop decisions</b> to the original (regime A: 22/132 dropped in every fold under both methods; regime B: 26, 22, 23, 22, 22 dropped per fold under both methods), so every downstream distance, Wasserstein value, and the closest-regime-to-external verdict (LOMFO, unchanged) are numerically identical. The audit trail is now correct; no manuscript number changes as a result.


#### Supplementary Note 33. Source/DOI-cluster bootstrap


The primary and Supplementary Note 8 uncertainty analyses resample external rows independently. Connected-component clustering over the strict cohort's formula-DOI bipartite graph (213 pre-aggregation retained rows, 204 formulas, 91 DOIs, reproducing Supplementary Note 4's counts exactly) yields 85 source clusters (largest = 10 rows). Resampling clusters instead of rows (2,000 iterations, same fixed seed) widens every model's external-MAE 95% CI, as expected (for example, extremely randomized trees [0.978, 1.464] at cluster level versus [1.032, 1.385] under this analysis's own row-level resampling). It changes no regime comparison's zero-exclusion status. After the pre-submission correction of the pooled elemental-property model (Supplementary Note 27), the row-level B-minus-A and C-minus-A rank-agreement CIs already include zero (B-minus-A Spearman rho -0.0952, row-level [-0.3339, 0.0476], cluster-level [-0.4048, 0.1190]; B-minus-A Kendall tau -0.1429, row-level [-0.4286, 0.0000], cluster-level [-0.4286, 0.0000]; C-minus-A Spearman rho -0.0714, row-level [-0.6190, 0.1667], cluster-level [-0.6429, 0.2619]; C-minus-A Kendall tau -0.0714, row-level [-0.5000, 0.0714], cluster-level [-0.6429, 0.2143]), and they remain so under clustering. The median-|MAE-gap| differences include zero under both resampling units, and the B-minus-A regret difference (0.1471) excludes zero under both (row-level [0.0337, 0.2638]; cluster-level [0.0052, 0.3122]). Point estimates are identical by construction. An earlier version of this analysis, computed before the pooled elemental-property model was corrected, found that clustering moved four rank-agreement CIs from excluding to including zero; that finding does not survive the correction, because the corrected row-level intervals already include zero. Same-source dependence still widens every interval, so the row-level CIs should be read as a lower bound on external-cohort uncertainty.


#### Supplementary Note 34. `__MISSING__`-family sensitivity


18 of 449 development-population rows lack a Family label and are filled with the `__MISSING__` sentinel, which is then treated as its own group for regimes B/C. Both variants below were rerun for the pooled elemental-property model only, after the pre-submission feature-lookup correction (Methods; Supplementary Note 27); the other seven models' numbers are unchanged from the historical analysis. <b>Variant A (exclude these 18 rows from evaluation; row-count-weighted recombination of already-frozen per-family MAE, no retraining):</b> regime-utility rank agreement and regret are <b>exactly unchanged</b> for both B-minus-A and C-minus-A (identical Spearman rho, Kendall tau, and regret, to four decimal places, with and without `__MISSING__`); the median-|MAE-gap| point estimate shifts modestly (B-minus-A: 0.2278 to 0.2888; C-minus-A: 0.0618 to 0.1361) but neither crosses the excludes-zero/includes-zero boundary in either direction. <b>Conclusion for Variant A: the primary result does not depend on how the 18 `__MISSING__` rows are handled in evaluation.</b>

<b>Variant B (treat each `__MISSING__` row as its own singleton group under Family-GroupKFold; genuine nested-CV rerun, regime B'):</b> the catastrophic blowup essentially disappears for both previously-unstable models (ridge 143.129 to 2.333; shallow MLP 969.424 to 1.763), while every other model shows a modest <i>increase</i> relative to regime B (e.g. catboost 1.487 to 1.842; pooled elemental-property model 2.702 to 2.688, essentially flat). Regime B's Spearman rank agreement with external ranking is already weak in the corrected primary comparison (0.5476, no longer significantly different from random CV; Table 3) and <b>falls further under B' (0.1905)</b>, and Kendall tau likewise falls from 0.3571 to 0.1429; the B'-minus-A rank-agreement 95% CIs clearly exclude zero in A's favor (Spearman [-0.7857, -0.1429]; Kendall [-0.6429, -0.0714]) even though neither B-minus-A difference does (Table 3) -- unlike an earlier analysis affected by the since-corrected feature-pipeline bug, B' no longer reverses the <i>sign</i> of B's rank agreement (both stay positive: 0.55→0.19 and 0.36→0.14), it only drives an already-non-significant positive association to a significantly worse one. Median |MAE gap| (B-minus-A: 0.2278 to 0.2834, CI still includes zero) and regret (unchanged at 0.1471, CI excludes zero both times) are not materially changed in direction. <b>Conclusion for Variant B: H1/H2 remain NOT SUPPORTED under this alternative grouping (no new support for family-aware validation), but this reveals a genuine fragility -- regime B's weak positive rank-agreement point estimate is not robust to an arbitrary, defensible implementation choice for the `__MISSING__` sentinel group, and degrades to a result statistically distinguishable from random CV's, in A's favor.</b> The primary comparison throughout this study uses the original, single, pre-specified `__MISSING__`-as-one-group convention, unchanged; this sensitivity is reported as an added limitation, not substituted into the headline result.


#### Supplementary Note 35. Chemical-system-GroupKFold sensitivity (regime E)


The exact-formula-disjoint control (regime D) removes only exact reduced-formula duplication. This note extends the control to the pymatgen element-set ("chemical system") level, following Supplementary Note 15's observation that 63 chemical systems (334 rows) share an element set across more than one distinct stoichiometry. 153 unique chemical systems span the 449-row development population (largest group 4.5% of the pool), so, unlike Family-GroupKFold, no single fold can strip an entire feature region from training; a genuine nested-CV rerun under this grouping (regime E) confirms this: the largest E-vs-A pooled-MAE ratio is 1.30x (composition attention), against up to 941.8x under regime B.

Regime E's regime-utility statistics are a genuine, unanticipated finding, reported as found. E's median |MAE gap| (0.1045) is substantially smaller than A's (0.4531), with a 95% CI clearly excluding zero in E's favor (delta -0.3486, 95% CI [-0.4263, -0.1370]) -- chemical-system-GroupKFold's internal error estimate is closer in <i>magnitude</i> to the external MAE than random CV's. Mechanically, E's internal MAEs are modestly higher than A's for every model (e.g. ridge 1.41 to 1.56, extra trees 0.75 to 1.19), because E's fold construction removes a mild form of composition redundancy that random CV does not control for, landing closer to the external MAE's ~1.2-1.8 range. Rank agreement is essentially tied with A (Spearman rho exactly equal, delta 0.0, 95% CI including zero, [-0.1667, 0.0714]; Kendall tau deterministically slightly lower for E, delta -0.0714, 95% CI [-0.0714, -0.0714]), and regret is worse for E (delta +0.0895, 95% CI [0.0019, 0.1726], excluding zero in A's favor).

This is not evidence that chemistry-family-awareness helps -- regimes B/C already answer that question in the negative -- because chemical systems are a much narrower, more numerous grouping (153 groups, largest 4.5% of the pool) than chemistry families (as few as 9 major groups, up to 47.4% of the pool in one fold); this is a different, weaker redundancy-control axis, not a stronger family-awareness test. The honest reading: some degree of composition-redundancy control beyond exact-formula, short of full family exclusion, improves internal-external MAE-magnitude calibration without the extrapolation-failure cost family exclusion causes, but does not improve, and slightly worsens, model-selection reliability.


#### Supplementary Note 36. Formula-balanced external-estimand sensitivity and formula-cluster bootstrap


<b>Spec:</b> `reports/remediation/specs/issue10_formula_balanced_sensitivity.md`, hashed before any number below was computed (`reports/remediation/specs/HASHES.txt`). <b>Analysis script:</b> `scripts/analysis/issue10_formula_balanced_sensitivity.py` (historical 7/8-model run; superseded for the pooled elemental-property model's row by `scripts/analysis/corrective01_issue10_formula_balanced_sensitivity.py` after Supplementary Note 27's correction). <b>Artifact:</b> `artifacts/historical/issue10_formula_balanced_sensitivity.json` (historical; retained in internal Git history, not included in the curated public release); `artifacts/authoritative/issue10_formula_balanced_sensitivity_corrected.json` (corrected 8-model view, authoritative for the numbers below).

<b>Motivation.</b> The primary external metrics assign equal weight to the strict Hargreaves cohort's aggregated formula-level records. As a post hoc identity check, this note asks whether an explicit equal-weight formula grouping -- the estimand that would be needed if several retained rows had instead shared one reduced formula -- changes external MAE or model ranking for the frozen 204-record strict cohort actually used by the one-shot external transfer (`artifacts/frozen/n6_external_transfer_primary.json`).

<b>Premise check.</b> `aggregate_by_formula` (`src/sse_transfer/data/hargreaves_cohort.py`) builds the strict cohort by grouping the 213 pre-aggregation retained rows by `reduced_formula` and emitting one aggregated formula-level record per group, using the unweighted median target within each group, <i>before</i> N6 ever reads a target value. The analysis script verifies this with `collections.Counter`, rather than assuming it or aborting on repeats: it computes `n_unique_reduced_formulas`, `n_repeated_formula_groups` (formula identities with count > 1) and `n_duplicate_excess_rows` (total rows minus unique formulas) directly from the frozen cohort file, and separately verifies -- by formula multiset, not by requiring uniqueness -- that each of the eight models' frozen predictions covers the identical formula population, so residuals and formulas cannot silently misalign even if a future cohort does contain repeats. For this frozen cohort: 204 rows, 204 unique `reduced_formula` values, <b>zero repeated-formula groups</b>, zero duplicate-excess rows. Every model's frozen prediction set independently confirms the same 204-formula multiset.

<b>Formula-balanced MAE.</b> Defined as MAE_formula,m = mean_f(mean_{i∈f}|y_i − ŷ_{i,m}|), implemented as an explicit group-then-average (verified on synthetic multi-member-group data in `tests/unit/test_regime_utility.py` to equal manual group averaging, and to differ from the plain row mean whenever group sizes are unequal). Given the premise check above, this is numerically identical to the row-weighted MAE for every model:

This note's own script (`scripts/analysis/issue10_formula_balanced_sensitivity.py`) correctly refuses to run against the corrected, non-primary external-transfer view (its authorization guard is designed to reject exactly this substitution); a separate script reusing the identical formulas and bootstrap procedure (`scripts/analysis/corrective01_issue10_formula_balanced_sensitivity.py`) recomputed every statistic below, including the formula-cluster bootstrap CIs, against the corrected eight-model view, without touching that guard or the historical one-shot lock.

<b>Regime-utility recomputation.</b> Feeding the formula-balanced external MAE into the same `regime_summary` function used for the primary comparison gives, for regimes A, B, C and D (8-model and 6-model subsets), statistics identical to the already-reported row-weighted values (median |gap|, Spearman ρ, Kendall τ, and regret all match to floating-point precision; e.g. A: 0.4531/0.6429/0.5000/0.0000, D: 0.4009/0.6429/0.5000/0.0000, matching the main-text and Supplementary Note 15 values exactly).

<b>Formula-cluster bootstrap.</b> Resampling unique formula groups (not rows) with replacement, 2,000 iterations, the same fixed seed (20260921) used by every other bootstrap in this study, gives external-MAE 95% CIs for all eight models and the regime-utility pairwise deltas B-minus-A, C-minus-A (from the corrected `artifacts/authoritative/n7b_regime_utility_nested_corrected.json`) and D-minus-A (from the corrected post hoc regime-D bootstrap in `artifacts/authoritative/phase1_factual_fixes_corrected.json`'s `item4_pairwise_diffs.formulaGKF_minus_A`). The script hard-checks each pairwise statistic's point delta against its pre-existing row-level reference to 1e-9 tolerance and raises if violated, because point-delta agreement is a required scientific invariant (given the premise check, a cluster bootstrap over singleton formula groups draws the same multiset of rows, with the same multiplicities, as a row bootstrap over individual rows, for any correct implementation of either). CI-endpoint agreement with the row-level reference is computed and reported rather than asserted, because the spec identifies a cluster bootstrap over singleton groups (`rng.choice`) and a row-level bootstrap over individual rows (`rng.integers`) as different pseudorandom draw sequences over the same distributional target, so a CI difference would reflect sampling noise, not a population-weighting effect. For this run, every one of the twelve pairwise point deltas (three pairs by four statistics) matched its reference to 1e-9, and every corresponding CI endpoint also matched exactly (zero observed difference) -- an empirically observed implementation-level identity, not a mathematical requirement, consistent with `Generator.choice(a, size=n, replace=True)` over `a = arange(n)` happening to call `Generator.integers(0, n, size=n)` internally under the current NumPy version; that bit-for-bit coincidence is a NumPy implementation detail, not a documented API guarantee.

<b>Decision.</b> External model ordering: unchanged. Validation-regime-utility magnitude and rank-agreement calibration: unchanged. Selection-regret conclusions: unchanged. The paper's deployment-conditional central claim: unaffected. Repeated-formula weighting is therefore not a vulnerability of the external estimate reported in this manuscript, because the cohort-construction pipeline already guarantees row and formula granularity coincide; this is reported as a verified finding rather than an assumption, and the check would need to be redone, not presumed, if a future external cohort were built without row-per-formula aggregation.
